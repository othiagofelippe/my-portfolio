Escreva uma spec para: $ARGUMENTS

Processo:

1. Pesquise o código relevante antes de escrever qualquer coisa (arquivos, padrões existentes, o que o @tfds já oferece)
2. Liste **SUPOSIÇÕES** explicitamente e peça correção antes de prosseguir
3. Produza a spec com: objetivo (1 parágrafo), escopo (o que entra e o que NÃO entra), critérios de aceitação verificáveis, arquivos afetados, riscos/trade-offs
4. Mantenha curto — uma spec de portfolio pessoal cabe em ~30 linhas
5. **Pare e aguarde aprovação.** Não implemente nada neste comando.
